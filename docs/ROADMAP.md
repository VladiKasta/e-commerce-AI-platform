# Дорожная карта проекта

План развития eCommerce Starter Kit по этапам. Этапы 1–10 — обязательная базовая версия (V1); сквозные обязательные требования базовой версии — в разделе «Сквозные требования V1»; расширения после неё собраны в разделе V1.1. Детали выполнения и текущий статус — в [PROGRESS.md](PROGRESS.md).

Этапы упорядочены по принципу **Backend First, Frontend Last** (перестройка 27.11.2026, см. [PROGRESS.md](PROGRESS.md)): этапы 1–3 — завершенные инфраструктура, Commerce API и поиск; этапы 4–8 — backend (корзина/checkout/заказы, покупатели, платежи/доставка, контент, SEO Content Management и приемка backend); этапы 9–10 — витрина (Commerce Client и composables, страницы и итоговая приемка).

## Этап 1. Инфраструктура и базовое развертывание ✅ (завершен)

Docker Compose (PostgreSQL, Redis, Meilisearch, Medusa, Nuxt), единый `.env`, автоматическая инициализация (миграции, идемпотентный seed, администратор, publishable API key), демо-витрина с реальными товарами, базовая документация и API-справочник.

## Этап 2. Commerce API и базовый типизированный API-клиент ✅ (завершен)

- Типизированный API-клиент storefront на базе официального `@medusajs/js-sdk` (2.23.0): `useCommerce()` c группами `products`, `categories`, `collections`, `regions`.
- Composables: `useCommerce` (транспорт) и `useStore` (регионы, валюта, форматирование цен).
- Региональные рассчитанные цены, пагинация, таймаут, отмена запросов, единая нормализация ошибок `CommerceError`.
- Демо-страницы: главная, `/catalog` (пагинация), `/product/:handle` (404 для отсутствующего товара) — все на Commerce Client.
- Автотесты: unit (31) + интеграционные на живой Medusa (20), `make test`.
- `docs/api.md` (все используемые маршруты Store API), `docs/commerce-client.md`, `docs/composables.md`.

- Корзина и checkout (этап 4): корзина, позиции, промокоды, доставка, payment collections/sessions, complete. **Безопасное хранение cart_id — серверное** (httpOnly-cookie/серверная сессия, без localStorage и URL) и **валидация обязательного email до complete** (сервером Medusa email не требуется — зафиксировано приемкой 4.4; подробности — [docs/checkout.md](checkout.md)).
- Авторизация (этап 5), покупатели и заказы: `/auth/customer/*`, профиль, адреса, история заказов; **контракты `useAuth`/`useCustomer`/`useOrders`/`useCart`/`useCheckout`/`usePayment` и требование серверного хранения JWT/session/cart_id (HttpOnly cookies + Nitro BFF) зафиксированы приемкой 5.4 — [docs/auth.md](auth.md)**.
- Оплата и доставка (этап 6): демонстрационные провайдеры оплаты (тестовая онлайн-оплата, оплата при получении), способы доставки.
- Контент (этап 7): информационные страницы и новости.
- SEO (этап 8): `useStoreSeo`, `useProductSeo`, `useCategorySeo`, `useSeoContent` — глобальный шаблон, переопределяемый индивидуальными значениями из `metadata.seo`.

## Этап 10. Storefront и итоговая приемка

Frontend-этап и финализация базовой версии (V1).

- UI-примитивы витрины (Tailwind), примеры компонентов и layout.
- Каталог (категории, сортировка, пагинация) и карточка товара (варианты, цены, изображения, наличие); SEO-мета каталога (базовый уровень; полная SEO-подсистема — этапы 8–9).
- Корзина и checkout: страницы корзины и оформления заказа; блокировка повторной отправки complete на клиенте — UX-рекомендация (серверная сериализация и защита от дублей заказов реализована этапом 4.5).
- Личный кабинет: профиль, адреса, история заказов; информационные страницы.
- SSR SEO-контента: компонент `SeoContent.vue`, серверный рендеринг SEO-текстов и метатегов (SEO-текст в исходном HTML без клиентского JavaScript, адаптивные изображения); динамические `sitemap.xml` и `robots.txt` (только опубликованные сущности, канонические URL); JSON-LD — Product (Offer), BreadcrumbList, Organization/WebSite; индексация каталога — пагинация и фасетные фильтры без индексируемых дублей (стратегию self-canonical/noindex выбрать при реализации и зафиксировать в PROGRESS.md); базовые 301-редиректы при изменении URL/смене handle (карта редиректов, серверная обработка на Nuxt); документация по переиспользованию.
- E2E и нагрузочное тестирование (изолированное окружение; тестовые заказы не создаются в production-БД — зафиксировано приемкой 4.4).
- Production-развертывание: сборка образов (`medusa build`, `nuxt build`), worker mode, reverse proxy, HTTPS; чек-лист развертывания.

## Сквозные требования V1

Обязательные требования базовой версии, реализуемые насквозь в рамках этапов 1–10 (не отдельным этапом); полнота проверяется на финальном тестировании (этап 10).

### Event-driven Extensibility

Расширение логики конкретного магазина событиями — только штатные механизмы Medusa v2: Event Bus (Redis), Subscribers, Workflows и Workflow Hooks. Собственная параллельная система событий **не разрабатывается**.

- Кастомная бизнес-логика магазина — отдельные модули, подписчики (`src/subscribers`) и предусмотренные точки расширения Medusa (Workflow Hooks), без изменения ядра Medusa и витрины.
- Собственные модули излучают события изменения данных, если они необходимы другим подсистемам (по образцу штатных событий Medusa); фактический состав эмиссии проверяется на установленной версии — по опыту этапа 3 не все события моделей излучаются автоматически (см. [PROGRESS.md](PROGRESS.md), решение №19).
- Названия событий и доступные Workflow Hooks сверяются с установленной версией Medusa (2.23.0) перед каждой реализацией.

Состав V1:

- Redis Event Bus — штатный `event-bus-redis` (включен с этапа 1).
- Примеры кастомных подписчиков — воспроизводимый шаблон добавления интеграции конкретного магазина.
- Обработка ошибок и идемпотентность обработчиков (штатные средства: ретраи и компенсации workflow-движка, идемпотентные подписчики).
- `docs/events.md`: перечень фактически поддерживаемых событий — payload, условия возникновения, примеры подписки; пополняется этапами по мере появления событий.
- Документация по добавлению клиентских интеграций без изменения ядра (на базе примеров подписчиков и Workflow Hooks).
