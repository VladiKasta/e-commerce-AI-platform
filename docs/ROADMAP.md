# Дорожная карта проекта

План развития eCommerce Starter Kit по этапам. Этапы 1–10 — обязательная базовая версия (V1); расширения после неё собраны в разделе V1.1. Детали выполнения и текущий статус — в [PROGRESS.md](PROGRESS.md).

## Этап 1. Инфраструктура и базовое развертывание ✅ (завершен)

Docker Compose (PostgreSQL, Redis, Meilisearch, Medusa, Nuxt), единый `.env`, автоматическая инициализация (миграции, идемпотентный seed, администратор, publishable API key), демо-витрина с реальными товарами, базовая документация и API-справочник.

## Этап 2. Commerce API и базовый типизированный API-клиент ✅ (текущий, завершен)

- Типизированный API-клиент storefront на базе официального `@medusajs/js-sdk` (2.23.0): `useCommerce()` c группами `products`, `categories`, `collections`, `regions`.
- Composables: `useCommerce` (транспорт) и `useStore` (регионы, валюта, форматирование цен).
- Региональные рассчитанные цены, пагинация, таймаут, отмена запросов, единая нормализация ошибок `CommerceError`.
- Демо-страницы: главная, `/catalog` (пагинация), `/product/:handle` (404 для отсутствующего товара) — все на Commerce Client.
- Автотесты: unit (31) + интеграционные на живой Medusa (20), `make test`.
- `docs/api.md` (все используемые маршруты Store API), `docs/commerce-client.md`, `docs/composables.md`.

## Этап 3. Meilisearch, индексация, поиск и фасетная фильтрация 🔧 (в разработке)

- 3.1–3.3 ✅: официальный Search Module Medusa 2.23 + провайдер Meilisearch (версионированные индексы, атомарное переключение), индексация товаров/вариантов/цен/остатков/категорий/характеристик, Store API `/store/catalog`, `/store/search`, `/store/search/suggestions` — фасеты с точными счетчиками уникальных товаров, variant-ориентированная фильтрация, OR/AND, disjunctive-пересчет; локальная оптимизация фасетного поиска (фасеты без активного фильтра — в базовом подзапросе, подтвержденные нули без count-запросов).
- 3.4 ✅ (завершен): Admin API характеристик товаров (модуль `catalog_attributes`) — CRUD характеристик, допустимые значения, привязки к категориям, значения товаров; zod-валидация, штатная авторизация `/admin/*`, каскадные удаления без «осиротевших» записей; 10 интеграционных тестов на живой Medusa (`make test`).
- 3.5.1 ✅ (завершен): страница управления характеристиками в Medusa Admin — пункт навигации «Характеристики», таблица, создание/редактирование/удаление с подтверждением, управление допустимыми значениями (UI Routes + штатные компоненты `@medusajs/ui`).
- 3.5.2 ✅ (завершен): привязки характеристик к категориям и настройки фильтрации в Medusa Admin — секция «Категории» на детальной странице (отображение с именами/хэндлами/позициями, добавление через выбор из реального каталога, удаление) через готовый маршрут замены набора (№23) + штатный `GET /admin/product-categories`; редактирование настроек фильтрации (тип отображения, позиция, единица, доступность) из 3.5.1 проверено на сохранность после перезагрузки.
- 3.5.3 ✅ (завершен): виджет «Характеристики товара» на карточке товара Medusa Admin (зона `product.details.after`) — доступные характеристики по категориям товара с семантикой backend (категория без привязок → все; объединение категорий без дубликатов; назначенные значения видны независимо от категорий), контролы по типу данных (строка/число/флажок/одиночный и множественный выбор), единицы и допустимые значения, сохранение/удаление значений; характеристики со штатной опцией (option_title — цвет/размер) не показываются, чтобы не дублировать Product Options.
- Остаток этапа: job сверки индекса, unit-тесты трансформации поисковых документов, docs/search.md + docs/filters.md + docs/indexing.md, OpenAPI-спецификация, MEILISEARCH_SYNONYMS/STOP_WORDS в .env.example.

## Этап 8. SEO-подсистема, информационные страницы и примеры layout

Обязательная часть базовой версии (V1). Принцип этапа — **Medusa First, Custom Last**: сначала штатные возможности Medusa, собственный код — только для пробелов; результат проверки фиксируется в PROGRESS.md до начала реализации.

- Аудит штатных возможностей (первая задача этапа): хранение SEO-атрибутов в нативном поле `metadata` товаров, категорий и коллекций Medusa + виджеты Medusa Admin поверх него; отдельный SEO-модуль создается только если `metadata` окажется недостаточно.
- SEO-виджеты в Medusa Admin для товаров, категорий и коллекций: Meta Title, Meta Description, Canonical URL, Robots, Open Graph (title, description, image, type).
- Глобальные шаблоны метатегов (генерация title/description из полей сущности) и индивидуальные SEO-настройки с приоритетом над шаблонами.
- Автоматическое SEO витрины: переиспользуемые composables Nuxt (товар, категория, коллекция, информационная страница) — шаблон, переопределяемый значениями из `metadata`.
- Динамические `sitemap.xml` и `robots.txt`: только опубликованные сущности и канонические URL.
- Структурированные данные JSON-LD: Product (Offer), BreadcrumbList, Organization/WebSite.
- Индексация каталога: канонические URL; пагинация и фасетные фильтры — без индексируемых дублей (стратегию self-canonical/noindex выбрать при реализации и зафиксировать в PROGRESS.md).
- Базовые редиректы при изменении URL (смена handle → 301): карта редиректов, серверная обработка на Nuxt.
- Информационные страницы, примеры layout, документация по переиспользованию.
- Обязательная документация: `docs/seo.md` (SEO-настройки, шаблоны, приоритеты), используемые API-маршруты — в `docs/api.md`, SEO-composables — в `docs/composables.md`.
