# AGENTS.md — правила работы над проектом

Этот файл задает постоянные правила для всех агентов и разработчиков, работающих над eCommerce Starter Kit. Правила действуют во всех этапах и задачах.

## Принципы

1. **Использовать официальные возможности Medusa.** Прежде чем писать собственный код, проверь, не существует ли уже штатный workflow, модуль, сервис или API-маршрут в Medusa v2 (и в `@medusajs/medusa/core-flows`). Коммерческая логика Medusa не дублируется.
2. **Не дублировать бизнес-логику.** Переиспользуем существующие workflows/services через контейнер Medusa. Общие утилиты выносятся в общие модули, а не копируются.
3. **Соблюдать KISS, DRY и YAGNI.** Не создавать абстракции, слои и файлы «на будущее». Не реализовывать функциональность за пределами текущего этапа.
4. **Использовать TypeScript** в strict-режиме во всех приложениях (`backend`, `storefront`). Без `any` без обоснования.
5. **Централизованно управлять credentials.** Все секреты и параметры окружения — только в корневом `.env` (шаблон `.env.example`). Новые переменные добавляются в `.env.example` и `docs/configuration.md`. Секреты не дублируются, не коммитятся и не попадают в клиентский код.
6. **Не создавать незадокументированные API-маршруты.** Любой новый маршрут (в `backend/src/api` или `storefront/server`) добавляется в `docs/api.md` в том же изменения, в котором реализуется.
7. **Обновлять документацию при изменении API.** Если изменился контракт, ответ, заголовок или параметр — обнови `docs/api.md`, `README.md` и затронутые разделы `docs/`.
8. **Проверять работоспособность после каждого этапа.** После завершения задач этапа запускать фактические проверки: `make lint`, `make typecheck`, доступность сервисов (`make status`), ключевые API-маршруты (curl), сценарий витрины.
9. **Не заявлять о прохождении тестов, которые не запускались.** В отчетах и в `docs/PROGRESS.md` фиксируются только фактически выполненные проверки с датой. Если окружение не позволяет выполнить проверку — явно указать это.
10. **Не реализовывать функциональность за пределами текущего этапа.** Состав этапа определяется `docs/ROADMAP.md`; изменения состава фиксируются в `docs/PROGRESS.md` с обоснованием.

## Технический контекст

- Стек и зафиксированные версии: Nuxt 4, Vue 3, Medusa v2, PostgreSQL, Redis, Meilisearch, Docker, pnpm workspace, Tailwind CSS (актуальные точные версии — в `package.json` и `docker-compose.yml`).
- Структура репозитория: `backend/` (Medusa), `storefront/` (Nuxt), `infrastructure/scripts/`, `docs/`.
- Управление: через корневой `Makefile` (`make init`, `make up`, `make down`, `make dev`, `make build`, `make logs`, `make status`, `make migrate`, `make seed`, `make lint`, `make typecheck`).
- Команды `make` не должны удалять данные и volumes (кроме явных операций сброса, которых на текущих этапах нет).

## Определение готовности (Definition of Done) для любой задачи

- [ ] Код проходит `make lint` и `make typecheck`.
- [ ] Проведена фактическая проверка затронутой функциональности (запуск, curl, визуальная проверка).
- [ ] Документация обновлена (`docs/api.md` при изменении API, `docs/PROGRESS.md` — всегда).
- [ ] Новые переменные окружения задокументированы (`.env.example`, `docs/configuration.md`).
- [ ] Не добавлено ничего из будущих этапов.
